# Deviations from system-one-adapter-python 0.2.1

This module ports
[system-one-adapter-python](https://github.com/typesafe-ai/system-one-adapter-python)
0.2.1 (commit `e1d4cc938204b22fc5a3c3aca7044072fe3f712d`) and behaves as it
does, except in the rows below. Each row names the Go test that pins the
difference, and the rows of [`port-test-matrix.md`](port-test-matrix.md) that
cite it, or `—` when no upstream test reaches the behaviour. Most of the
tests are not written yet (their matrix rows say `planned`); until a test
exists, its row states the behaviour the port is built to have.

| # | Deviation | Why | Test | Matrix rows |
| --- | --- | --- | --- | --- |
| DV1 | Sync only: there is no async client and no async provider. Upstream's tests that run once with the sync client and once with the async one become one Go case, and its asyncio concurrency tests become tests with goroutines. | Go has no separate async API: one `*Adapter` serves concurrent calls, each with its own `context.Context`. | the matrix rows that cite DV1 | FM1, FM4-FM9, FM11, FM12, GT1-GT3, OT1, OT3, OT4, PL1-PL9, PL11, PL13, PN1-PN4, PR13, PR14, RT1 |
| DV2 | Cancellation is the context's: a cancelled call returns `ctx.Err()` without a Report. `Close` takes no context, so upstream's cases that cancel an async close have no counterpart. This covers cancellation only: a call whose deadline passes returns the timeout `*Error` with its Report. | The TypeSafe SDK returns the context's error for a cancelled call, and a Go `Close` has no waiter that a caller could cancel. | `TestCancelledCallReturnsContextError`; the deadline case of `TestClassificationOrder` | PL5 (its `cancelled` case), PL10, PL12 |
| DV3 | Retry settings are `adapter.RetryPolicy`, with the builder names of the TypeSafe SDK's `RetryPolicy`; upstream's `exceptions` set is expressed with `Predicate`; a per-call policy is passed with `ContextWithRetry` instead of a `retry=` argument. | The Adapter retries each provider request itself, so it has its own settings type; a call through the TypeSafe SDK has no `retry=` argument to carry it. | `TestRetryPolicy*`, `TestContextWithRetry` | FM4 |
| DV4 | Usage and debug data are the typed `Report`, read with `ReportOf` from a response and with `ReportFromError` from an error; its JSON keeps upstream's member names and order. | Go callers read typed values; the SDK's response type cannot carry extra fields. | `TestReportJSONMatchesUpstreamShape` | — |
| DV5 | Serialising the SDK's response (`SystemOneResponse.MarshalJSON`) drops the Adapter's members; `Report.MarshalJSON` or the raw response body keeps them. Upstream's `model_dump_json` keeps both in one object. | The TypeSafe SDK's response type is not changed by this module and cannot be extended. | `TestSDKQuestionsAndResponseSerialization` | FM1 |
| DV6 | `debug_info.provider` is the Go type path of the provider, not the Python class path. | The language differs. | `TestReplayReferenceShape` (the member is normalised) | LV1 |
| DV7 | `llm_response` is the provider's response body as received, not a vendor SDK's `model_dump`: OpenAI's numbers keep the spelling of the wire, and Gemini's has no SDK-added `id` or `output_text` and keeps the members the Python SDK drops. | No vendor SDK is used; the providers are written on `net/http`. | `TestReplayReferenceShape` (compared with the cassette body) | LV1 |
| DV8 | The correction prompt carries the Go validator's message instead of pydantic's `str(ValidationError)`; the fixed text around it is upstream's. | There is no pydantic. No recorded exchange holds a correction turn, so replay does not depend on the text. | `TestCorrectionPromptNamesTheFailure` | FM6, FM11 |
| DV9 | The provider and the model are chosen by one model string; an injected provider is registered by name; there is no error for a missing optional dependency, because all three providers are compiled in. | A call through the TypeSafe SDK carries one `model` string, and the providers are part of this module. | `TestResolveModel` | FM12, PL3, PR15, PR16 |
| DV10 | Lifecycle. There is no context manager: `NewClient` hands the Adapter to the SDK client, whose `Close` closes it once. The SDK returns the Adapter's cleanup error from its first `Close` and nil from a second, so a failed cleanup is retried by a later close only when the caller calls `(*Adapter).Close` again. `Close` waits for running calls to return before it closes the providers, while upstream's `close()` leaves that to the caller; so `(*Adapter).Close`, and `(*typesafe.Client).Close` with it, block until running calls end, and a caller who needs a bounded close cancels those calls first. | Closing a provider's connections under a running call would make the call open new ones. | `TestNewClientCloseClosesAdapter`, `TestCloseContinuesAfterFailure`, `TestCloseWaitsForRunningCalls`, `TestCloseAfterProviderPanic` | PL1 |
| DV11 | Exceptions reach the caller as the TypeSafe SDK's error types. A provider status keeps its code, so a provider 401 is an `*APIError` whose `IsAuthentication()` is true. A non-answer, an unclassified provider error and the Adapter's own encoding failure answer 424 (kind `other`), a status upstream has no counterpart for. | The Adapter answers over HTTP to the SDK, which builds the error; 424 is outside the SDK's retry set, so a caller's retry policy does not re-run a billed evaluation that upstream would not retry. | `TestFailureClasses` | FM10, UE1 |
| DV12 | A provider that cannot be built (no key, `max_tokens <= 0`) fails the call with status 400 and error type `provider_config` instead of raising the vendor's exception. | The failure crosses the HTTP seam to the SDK. | `TestProviderConfigFailure` | — |
| DV13 | The schema is written in pydantic's key order for every provider and mode. In `probabilities-native` mode, upstream's OpenAI and Anthropic SDKs reordered the schema object in place, so their order reached the recorded request bodies and upstream's own debug data. The value is equal in every case; replay matches a request body by value, and the comparison with upstream's expected responses compares `schema` and `request` by value. | No vendor SDK reorders the schema. | `TestNativeSchemaEqualsCassette`, `TestReplayReferenceShape` | — |
| DV14 | There is no error-translation layer (`translate_error`, `translating`): the providers return typed errors where the HTTP call ends. Upstream's pass-through and re-raise tests have no counterpart beyond the classification tests. | The providers are written on `net/http`, so there are no vendor exceptions to translate. | `TestProviderErrorClassification` | UE3, UE4 |
| DV15 | Questions are validated from the request JSON. The Go SDK's question values cannot be changed after `Prepare`, so upstream's case of a changed and re-validated question becomes a case with a raw request body. | The Adapter receives the questions as the SDK's request body. | `TestQuestionsValidatedFromWire` | SC2 |
| DV16 | Each provider the Adapter builds has its own `*http.Client`; there is no vendor retry or pool setting to switch off (upstream sets `max_retries=0`, and Gemini's `retry_config` to `None`). | No vendor SDK is used. | `TestRetryPolicyControlsHTTPAttempts` | RT1 |
